# LLM 호출은 httpx2 위에서 직접 하고, SSE 파싱과 tool_call 조립을 직접 구현한다

이 하네스는 모델과 실제로 주고받는 내용을 SDK에 맡기지 않고 직접 다룹니다. 공식 SDK나 LangGraph를 쓰면 다음과 같은 부분이 감춰집니다.

- 스트림 형식
- tool_call 델타 조립
- usage 집계
- 오류 처리

그래서 HTTP 클라이언트(httpx2)만 쓰고 그 위는 직접 만듭니다. 공식 openai SDK와 httpx2에 내장된 `client.sse()`는 정답 비교 기준으로만 씁니다. 테스트에서 같은 입력을 넣었을 때 내 구현과 같은 결과를 내는지 확인하는 용도입니다.

## Considered Options

- **공식 openai SDK:** 가장 쉽지만, 직접 다루려는 부분이 전부 SDK 안에 감춰집니다.
- **LangGraph:** 핵심 모듈에는 쓰지 않습니다. 공식 기준선을 잰 뒤, 같은 과제 세트로 LangGraph 버전을 만들어 비교하는 실험으로만 둡니다.
- **httpx:** httpx2의 원본입니다. 0.28.1(2024-12) 이후로는 최소한의 유지보수만 하고 있습니다. 또 openai SDK 3.x가 httpx2로 옮겨 갔기 때문에, httpx를 쓰면 HTTP 스택 두 개를 함께 두게 됩니다.
- **aiohttp:** 비동기 스트리밍은 지원합니다. 하지만 openai SDK와 전송 계층이 달라져서, 정답 비교에서 결과가 다를 때 원인을 파싱 쪽으로 좁히기 어렵습니다.

## Consequences

- API에 새 기능(새 이벤트 타입 등)이 생겨도 SDK가 대신 따라가 주지 않습니다. 회귀는 정답 비교 테스트로 잡습니다.
- 핵심 모듈에서 httpx2의 `client.sse()`를 쓰면 이 결정을 깨는 것입니다.
