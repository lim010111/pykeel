# EXAONE 호스팅 API 조사 (2026-11-18 기준)

> 2026-11-18 서브에이전트가 1차 출처로 조사한 보고서다. 처음에는 임시 폴더에 저장했으나 재부팅으로 사라져, 2026-11-19에 대화에 남아 있던 전문으로 다시 만들었다. 다운로드한 원본 페이지는 복구하지 못했다.

API는 호출하지 않았다. 근거는 다음 1차 출처다.
- LG AI연구원 EXAONE API Platform 문서(docs.exaone.ai)
- LG AI연구원 공식 뉴스
- Hugging Face의 LGAI-EXAONE 모델 카드와 파일
- FriendliAI 공식 문서와 changelog
- vLLM 공식 문서
- LG-AI-EXAONE GitHub 조직

각 항목에서 **확인**은 1차 출처에 적힌 내용이고, **추정**은 출처에서 끌어낸 해석이다.

## 요약

- **무료 호스팅:** 지금 무료로 쓸 수 있는 호스팅 EXAONE은 LG AI연구원 자체 **EXAONE API Platform의 K-EXAONE 2.5(`k-exaone_v2.5`) 하나**다. 2026-11-09에 열렸고, 기본 한도는 **하루 100회**, API key 유효기간은 **30일**이다. 약관은 **비상업적 이용**만 허용한다.
- **FriendliAI:** 서버리스(Model APIs)에 EXAONE 계열이 남아 있지 않다. K-EXAONE 2.0은 2026-09-06에 내려갔고, 앞서 있던 K-EXAONE 무료 행사는 2026-01-28에 끝났다.
- **엔드포인트:** 공식 문서에 나오는 것은 `POST https://api.exaone.ai/v1/chat/completions`(OpenAI 호환) 하나다. Responses API는 어디에도 나오지 않는다.
- **추론:** 항상 켜져 있고 끌 수 없다. `reasoning_effort`로 강도를 조절하고, 추론 내용은 `reasoning_content`로 따로 온다. 이전 턴 추론을 유지하려면 `chat_template_kwargs.preserve_thinking`을 쓴다.
- **tool calling:** Models 페이지에는 기능으로 적혀 있다. 그러나 엔드포인트 레퍼런스에는 `tools`, `tool_choice`, `parallel_tool_calls`, `tool` role이 나오지 않는다.
- **모델 식별:** 응답의 `model`은 `k-exaone_v2.5`이고 날짜 스냅샷이 붙지 않는다. 대신 `metadata.weight_version` 필드가 온다(예시 값은 `"default"`). Changelog 페이지는 있고, 항목은 하나뿐이다.

## 1. 호스팅 모델, 제공처, 무료 구간, 속도 제한

**결론:** 호스팅 API로 쓸 수 있는 최신 EXAONE은 EXAONE API Platform의 K-EXAONE 2.5뿐이고, 지금은 무료다. 기본 한도는 하루 100회이며, 선택 동의를 하면 하루 한도가 늘어난다(수치 미공개). RPM과 TPM은 공개되어 있지 않다.

**확인**

- **EXAONE API Platform(LG AI연구원 자체)**
  - Changelog의 2026-11-09 항목: "EXAONE 파운데이션 모델을 이제 API로 사용할 수 있습니다. 본 서비스는 현재 무료로 제공됩니다." 제공 모델은 "K-EXAONE 2.5(750B)"와 "EXAONE Tabular" 두 가지다. https://docs.exaone.ai/ko/docs/changelog
  - FAQ: "EXAONE API Platform에서 제공되는 모든 API는 무료로 제공되고 있습니다." https://docs.exaone.ai/ko/terms/faq
  - LG AI연구원 공식 뉴스: 2026-11-09 NVIDIA AI Day Seoul에서 발표했다. K-EXAONE 2.5는 8월 공개 모델(K-EXAONE 2.0)에 추가 학습을 한 "기술 검증 모델"이다. 개발자, 스타트업, 기업, 연구기관 누구나 API key만 받으면 "별도 비용 없이" 쓸 수 있다고 했다. 무료 기간과 한도는 적혀 있지 않다. https://www.lgresearch.ai/news/view?seq=754 (영문 https://www.lgresearch.ai/news/view?seq=755)
  - Models 페이지 사양: 750B(Active 31B), 텍스트 전용, 한국어와 영어. https://docs.exaone.ai/ko/docs/models
- **무료 이용 조건(약관과 FAQ)**
  - 회원가입과 로그인을 해야 key가 나온다. key는 계정당 하나다. https://docs.exaone.ai/ko/terms/faq

  - 만 19세 이상만 쓸 수 있다. 소재 국가를 정확히 입력해야 하고, 수출통제와 제재 법령을 지켜야 한다. 약관 8조.
  - 회사는 "비독점적, 양도 불가능, 취소 가능한 **비상업적** 이용 권한"을 준다. 영리 목적으로 쓰거나, API를 제품이나 서비스에 연동해 제3자가 모델을 호출하게 하는 것은 금지된다. 약관 2조 1항.
    - 공식 뉴스는 "서비스 개발과 연구에 활용"할 수 있다고 쓰고 있어 표현이 서로 다르다. 약관 서문에 따르면 이 약관은 Showroom 약관보다 우선한다.
  - 입력값과 결과물은 기본적으로 회사가 모델 학습에 쓸 수 있다. 이용자가 거부하면 그때부터 쓰지 않는다. 약관 2조 3항.
  - 금지 행위에 해당하는 것들:
    - 반복적인 동일 요청, 무작위 파라미터 테스트, 초당 요청 수 급증 같은 비정상 트래픽(자동 차단될 수 있음, 4조 1항)

**추정**

- 사용자가 아는 'EXAONE 무료 구간'은 지금 시점에서는 EXAONE API Platform의 K-EXAONE 2.5를 가리킬 가능성이 높다. FriendliAI 무료 행사는 이미 끝났다.
- 에이전트 루프에서는 tool 호출 한 턴이 API 호출 1회다. 그러므로 하루 100회는 몇 개 작업 분량에 그칠 수 있다.
- docs.exaone.ai 번들에 "EXAONE 4.5" 엔드포인트 문서 문자열과 `/docs/k-exaone-2.0` 링크가 남아 있다. 그러나 두 페이지 모두 404다. 예전에 제공했거나 제공을 계획했던 흔적으로 보이며, 지금 제공 중이라는 근거는 아니다.

## 2. 엔드포인트 형식, base URL, 인증, Responses API

**결론:** OpenAI 호환 Chat Completions다. base URL은 `https://api.exaone.ai/v1`이고, 인증은 `Authorization: Bearer <key>`다. Responses API는 공식 문서 어디에도 나오지 않는다.

**확인**

- `POST /v1/chat/completions`. 문서 원문은 "EXAONE API는 OpenAI Compatible API를 지원합니다"이고, 모델 ID는 `k-exaone_v2.5`다. https://docs.exaone.ai/ko/docs/k-exaone-2.5
- 기본 URL은 `https://api.exaone.ai`다(Quick Start). Agent 가이드는 base URL을 `https://api.exaone.ai/v1`로 적는다. https://docs.exaone.ai/ko/docs/quick-start , https://docs.exaone.ai/ko/docs/agent-start
- 인증은 `Authorization` 헤더에 Bearer 토큰 형식으로 넣는다. https://docs.exaone.ai/ko/docs/authentication . FAQ는 401이 계속 나는 주된 원인으로 'Bearer' 누락을 꼽는다.
- 오류 본문에는 `result_code`와 `description`이 온다. 상태 코드는 400, 401, 404, 422, 429, 500이다. https://docs.exaone.ai/ko/docs/error-codes
  - 예: `{'result_code': 401, 'description': 'Not authorized'}` (FAQ)
  - OpenAI의 `{"error": {...}}` 형식과는 다르다.
- 응답은 `object: "chat.completion"`과 `chat.completion.chunk`(SSE, `data: [DONE]`로 끝남)로 온다.
- 문서 전체(ko/en 엔드포인트, Quick Start, Agent 가이드, Models, FAQ, 약관)에서 `/v1/responses`, "Responses API", `/v1/models`는 검색되지 않는다.
- Agent 가이드의 Hermes 설정 예시는 `transport: chat_completions`를 쓴다.

**추정**

- 프로젝트 문서의 "EXAONE은 OpenAI 호환 Chat Completions만 지원한다"는 공식 문서가 Chat Completions만 기술한다는 사실과는 맞는다. 다만 `/v1/responses`가 정말 없는지는 호출하지 않고서는 확인할 수 없다.

## 3. API 수준 tool calling

**결론:** 공식 문서는 tool calling을 지원 기능으로 적는다. 하지만 엔드포인트 레퍼런스는 `tools`, `tool_choice`, `parallel_tool_calls`, `tool` role, `tool_call_id`를 하나도 기술하지 않는다. K-EXAONE 2.5의 chat template은 공개되어 있지 않다. 공개된 K-EXAONE 2.0 template은 Qwen3-Coder식 XML 태그로 tool을 호출한다.

**확인**

- Models 페이지의 Features 항목: "Chat / Tool calling / Structured outputs / Code generation / Streaming". https://docs.exaone.ai/ko/docs/models
- 엔드포인트 레퍼런스의 요청 필드는 다음이 전부다. `tools`, `tool_choice`, `parallel_tool_calls`, `response_format`은 없다. https://docs.exaone.ai/ko/docs/k-exaone-2.5
  - `model`, `messages`
  - `messages[].role`(system / user / assistant), `messages[].content`(string)
  - `max_tokens`, `stream`, `stream_options.include_usage`
  - `temperature`, `top_p`, `top_k`, `presence_penalty`
  - `reasoning_effort`, `chat_template_kwargs.preserve_thinking`
- 응답 예시의 `message`에는 `tool_calls: null`과 `function_call: null` 필드가 들어 있다.
- Agent 가이드의 내용(https://docs.exaone.ai/ko/docs/agent-start):
  - "모델이 반환한 호출을 harness가 실행하고 결과를 다시 전달합니다. 도구를 한 번 호출한 뒤 최종 답변까지 이어지는지 확인합니다."
  - "텍스트·reasoning·tool calling delta를 harness가 처리합니다. tool 인자가 완성된 뒤 실행되는지, 다음 턴까지 이어지는지 확인합니다."
  - OpenCode 설정 예시에서 `capabilities.tools: true`로 선언한다.
- K-EXAONE 2.5 가중치와 template은 공개되지 않았다. HF LGAI-EXAONE 조직의 최신 모델은 K-EXAONE-2.0 계열(2026-07-29~30)이고, GitHub LG-AI-EXAONE 조직에도 2.5 저장소는 없다. https://huggingface.co/api/models?author=LGAI-EXAONE&sort=createdAt&direction=-1 , https://github.com/LG-AI-EXAONE
- K-EXAONE 2.0 chat template의 tool 형식. https://huggingface.co/LGAI-EXAONE/K-EXAONE-2.0-750B-A37B/blob/main/chat_template.jinja
  - 역할 토큰: `<|system|>`, `<|user|>`, `<|assistant|>`, `<|tool|>`, `<|tool_declare|>`. 턴은 `<|endofturn|>`로 끝난다.
  - tool 선언은 `<|tool_declare|>` 턴에 `# Tools` 안내문과 함께 tool마다 `<tool>{JSON}</tool>`로 넣는다.
  - 호출 형식:
    ```
    <tool_call>
    <function=NAME>
    <parameter=ARG>
    VALUE
    </parameter>
    </function>
    </tool_call>
    ```
  - 한 assistant 턴 안에 여러 `<tool_call>`이 줄바꿈으로 이어질 수 있다. template이 `msg.tool_calls`를 순회한다.
  - 결과는 `<|tool|>` 턴 안에 `<tool_result>...</tool_result>`로 넣는다. 연속된 tool 메시지는 한 `<|tool|>` 턴으로 묶인다. 결과에는 `tool_call_id`나 이름이 들어가지 않는다.
  - template은 `arguments.items()`를 호출하므로 arguments를 객체(매핑)로 기대한다.
- K-EXAONE 2.0 모델 카드의 서빙 옵션. https://huggingface.co/LGAI-EXAONE/K-EXAONE-2.0-750B-A37B
  - vLLM: `--reasoning-parser qwen3 --enable-auto-tool-choice --tool-call-parser qwen3_xml`
  - SGLang: `--reasoning-parser qwen3 --tool-call-parser qwen3_coder`
  - 카드의 tool calling 예시는 OpenAI SDK의 `tools=[{"type":"function",...}]`를 쓴다.
- EXAONE 4.5는 형식이 다르다. https://huggingface.co/LGAI-EXAONE/EXAONE-4.5-33B
  - JSON을 넣는 `<tool_call>{"name": ..., "arguments": ...}</tool_call>` 형식이다.
  - vLLM `--tool-call-parser hermes`

**추정**

- 호스팅 API도 OpenAI식 `tools`를 받고 `message.tool_calls`를 돌려줄 가능성이 높다. 근거는 Models 페이지의 기능 목록, Agent 가이드, 그리고 응답에 `tool_calls` 필드가 있다는 점이다.
- 응답에 SGLang 고유 필드로 보이는 것(`matched_stop`, `metadata.weight_version`)이 있다. 그래서 백엔드는 SGLang일 가능성이 있다. 그렇다면 `tool_choice`와 병렬 호출의 동작도 SGLang 구현을 따를 것이다.
- 2.5가 2.0을 추가 학습한 모델이므로 tool 태그 형식도 2.0과 같을 가능성이 있다. 어느 쪽도 문서로 확인되지는 않는다.
- 병렬 호출은 template 수준에서는 표현할 수 있다. 다만 결과가 ID 없이 순서로만 대응되므로, 결과 메시지 순서는 호출 순서와 같아야 할 것으로 보인다.

## 4. 추론(thinking) 모드

**결론:** K-EXAONE 2.5는 항상 추론한다. 끌 수 없고 `reasoning_effort`로 강도만 바꾼다. 추론 내용은 `reasoning_content`(스트림에서는 `delta.reasoning_content`)로 `content`와 나뉘어 온다. 다음 턴 유지 여부는 `chat_template_kwargs.preserve_thinking`이 결정하고, 에이전트 용도에는 `true`를 권한다.

**확인** (https://docs.exaone.ai/ko/docs/k-exaone-2.5 , 영문 https://docs.exaone.ai/en/docs/k-exaone-2.5)

- 영문 문서: "K-EXAONE 2.5 always reasons before answering, so enable_thinking is automatically set to true and can't be disabled."
- `reasoning_effort`의 허용값과 기본값은 문서마다 다르다.
  - 엔드포인트 레퍼런스: `low` / `high` / `max`, 기본값 `max`. low는 빠른 응답, high는 수학과 코딩, max는 정확도가 응답 시간보다 중요한 고난도 문제에 권한다.
  - Agent 가이드: `low` / `medium` / `high` / `max`. 연결 예시는 `medium`을 쓴다. https://docs.exaone.ai/ko/docs/agent-start
- 응답 형태
  - 추론은 `message.reasoning_content`, 최종 답변은 `message.content`에 담긴다. 추론 토큰 수는 `usage.reasoning_tokens`로 온다(`completion_tokens_details` 안이 아니라 `usage` 바로 아래).
  - 스트림 순서는 다음과 같다:
    1. `delta.role`
    2. `delta.reasoning_content` 조각들
    3. `delta.content` 조각들
    4. `finish_reason`
    5. usage 청크(`choices: []`)
    6. `[DONE]`
  - `content` 앞에 `"\n\n"`이 붙을 수 있다.
  - Quick Start의 비스트림 예시에는 `reasoning_content`가 있지만, 엔드포인트 페이지의 비스트림 예시에는 없다. https://docs.exaone.ai/ko/docs/quick-start
- `max_tokens`는 "추론 과정 포함"이다. "Hello" 예시에서도 추론 토큰이 209개 쓰였다(`max_tokens: 512`).
- `chat_template_kwargs.preserve_thinking`(기본값 `false`): "멀티턴 대화에서 이전 assistant 턴의 추론 과정을 입력에 남길지 여부. false면 마지막 유저 메시지 이후의 추론만 유지". 권장 설정은 "Agent로 사용하거나 멀티턴 대화에서 이전 추론 과정을 유지할 때: … `preserve_thinking=true`"다.
- Agent 가이드:
  - "이전 assistant의 reasoning과 tool 호출 이력을 다음 요청에 전달하는 것은 agent의 별도 동작입니다."
  - OpenCode 예시의 `compatibility.reasoningField: "reasoning_content"`는 "스트리밍에서 읽고 다음 요청의 assistant 이력에 다시 담을 reasoning 필드"라고 설명한다.
- K-EXAONE 2.0 template의 동작. https://huggingface.co/LGAI-EXAONE/K-EXAONE-2.0-750B-A37B/blob/main/chat_template.jinja
  - assistant 메시지의 `reasoning_content` 필드를 읽는다. 없으면 `content` 안의 `<think>…</think>`를 떼어 낸다.
  - `preserve_thinking`이 참이거나, 그 메시지가 마지막 user 메시지(content가 문자열인 것) 뒤에 있을 때만 `<think>` 안에 추론을 넣는다. 그 밖에는 빈 `<think>\n\n</think>`를 넣는다.
  - 2.0은 `enable_thinking=False`로 비추론 모드를 쓸 수 있다. template에 `reasoning_effort` 처리는 없다.

**추정**

- 2.5도 같은 방식이라면, 추론을 유지하려면 클라이언트가 이전 assistant 메시지에 `reasoning_content`를 다시 넣어 보내야 한다. 보내지 않으면 유지할 추론 자체가 없다.
- `preserve_thinking=false`여도 같은 user 질의 안의 tool 루프(assistant → tool → assistant)에서는, 돌려보낸 추론이 입력에 남는 것으로 보인다. tool 결과는 user 메시지가 아니기 때문이다.
- 호스팅 API가 입력 메시지의 `reasoning_content` 필드를 받는지는 레퍼런스에 없다. 레퍼런스는 `role`과 `content`만 기술한다.
- `reasoning_effort`는 2.0 template에 없으므로, 2.5에서 새로 생겼거나 서버 쪽 기능으로 보인다.

## 5. 응답의 `model` 필드와 changelog

**결론:** `model`은 `"k-exaone_v2.5"`로 찍히고, 날짜나 빌드 구분자가 없다. 대신 `metadata.weight_version`과 `metadata.weight_versions[]`가 온다(예시 값 `"default"`). `system_fingerprint`는 `null`이다. Changelog는 있지만 항목이 출시 공지 하나뿐이다. 약관상 버전은 예고 없이 바뀔 수 있다.

**확인**

- 응답 예시(비스트림과 스트림 모두)의 `"model": "k-exaone_v2.5"`, `"metadata": {"weight_version": "default", "weight_versions": [{"version": "default", "start": 0, "end": 218}]}`, `"system_fingerprint": null`. https://docs.exaone.ai/ko/docs/k-exaone-2.5
  - `weight_version`의 의미는 문서에 설명이 없다.
- 응답마다 `x-request-id` 헤더가 붙는다. https://docs.exaone.ai/ko/docs/rate-limits
- Changelog 페이지: "버그 수정, 신규 기능, 개선 사항, 기능 제거, 보안 패치 등의 변경 이력"을 싣는다고 적혀 있다. 현재 항목은 2026-11-09 하나다. https://docs.exaone.ai/ko/docs/changelog

**추정**

- `weight_version`과 `weight_versions`(토큰 구간 start/end)는 SGLang이 가중치 갱신을 추적할 때 쓰는 필드와 모양이 같다. 가중치가 바뀌면 이 값이 바뀔 수도 있지만, LG가 그렇게 운용한다는 문서는 없다.
- `model` 값만으로는 같은 `k-exaone_v2.5` 안에서 가중치가 바뀌었는지 구분하지 못할 수 있다.

## 6. 컨텍스트, 최대 출력, 권장 샘플링, tool calling 권장 사항

**결론:** 컨텍스트는 524,288 토큰이고, 입력과 `max_tokens`의 합이 이 값을 넘으면 400을 돌려준다. 권장 샘플링은 `temperature=1.0`, `top_p=0.95`이고 이 값이 기본값이기도 하다. 에이전트 용도에는 `preserve_thinking=true`를 권한다.

**확인**

- K-EXAONE 2.5(API)
  - 컨텍스트와 출력
    - "최대 Context length는 524,288 토큰입니다. 입력 토큰 수와 max_tokens의 합이 이 값을 넘으면 400 에러를 반환합니다." https://docs.exaone.ai/ko/docs/k-exaone-2.5
    - Models 페이지: Context length 512K, Max output tokens 512K, Knowledge cutoff 2026-01, Speed Medium. https://docs.exaone.ai/ko/docs/models
    - `max_tokens`의 기본값은 문서에 없다.
  - 파라미터 기본값: `temperature` 1.0(범위 0.0~inf), `top_p` 0.95, `top_k` -1, `presence_penalty` 0.0, `reasoning_effort` `max`, `preserve_thinking` false.
  - 권장 설정: 일반 용도는 `temperature=1.0`, `top_p=0.95`. 에이전트나 멀티턴에서 추론을 유지할 때는 여기에 `chat_template_kwargs.preserve_thinking=true`를 더한다.
  - Agent 가이드의 tool calling 권장(https://docs.exaone.ai/ko/docs/agent-start):
    - tool을 한 번 호출한 뒤 최종 답변까지 이어지는지 확인한다.
    - 스트리밍에서는 tool 인자가 완성된 뒤 실행되는지, 다음 턴까지 이어지는지 확인한다.
    - 대화 이력과 출력이 context 한도에 들어가는지 고려한다.
    - `reasoning_effort`(추론 강도)와 `temperature`/`top_p`(sampling)는 서로 다른 설정이므로 구분한다.
- K-EXAONE 2.0(공개 가중치). https://huggingface.co/LGAI-EXAONE/K-EXAONE-2.0-750B-A37B
  - 사양: Context 262,144, Knowledge cutoff 2025 2Q, 750B/37B active.
  - 권장: `temperature=1.0`, `top_p=0.95`, 에이전트나 deep research 같은 장기 작업에는 `preserve_thinking=True`.
  - 예시는 `max_tokens=32768`이고, OpenCode 예시의 `limit.output`도 32768이다.
  - `generation_config.json`도 temperature 1.0, top_p 0.95다.
- EXAONE 4.5-33B. https://huggingface.co/LGAI-EXAONE/EXAONE-4.5-33B
  - 사양: Context 262,144, Knowledge cutoff 2024-12.
  - 권장: 일반 용도 `temperature=1.0, top_p=0.95, presence_penalty=1.5`, 텍스트 전용 입력 `temperature=1.0, top_p=0.95`. `enable_thinking`의 기본값은 True다.

## 7. 무료 구간을 못 쓰게 될 때의 대안과 라이선스

**결론:** K-EXAONE 2.5는 가중치가 공개되지 않았다. 자체 서빙 후보는 공개 가중치 K-EXAONE 2.0(Apache 2.0, 대형), EXAONE 4.5-33B(NC 라이선스, 단일 H200), K-EXAONE 236B다. 셋 모두 비상업 연구 용도의 사용은 라이선스상 허용된다. 호스팅 대안으로 FriendliAI 서버리스에는 지금 EXAONE이 없고, 유료 Dedicated Endpoints만 남아 있다.

**확인**

- **K-EXAONE-2.0-750B-A37B** (FP8, NVFP4, DSpark 변형 있음). https://huggingface.co/LGAI-EXAONE/K-EXAONE-2.0-750B-A37B
  - 라이선스는 Apache 2.0이다.
  - 카드의 서빙 예시: 8×H200 노드 2대(TP16)이고, 카드는 vLLM, SGLang, transformers 포크 설치를 안내한다. B200에서는 `--disable-prefill-cuda-graph`가 필요하다는 노트가 있다.
  - vLLM 최신 공식 문서의 지원 모델 표에는 `ExaoneMoeForCausalLM` 행이 "K-EXAONE, K-EXAONE-2"로 올라 있다. https://docs.vllm.ai/en/latest/models/supported_models.html
- **EXAONE-4.5-33B** (VLM; FP8, AWQ, GGUF 변형 있음). https://huggingface.co/LGAI-EXAONE/EXAONE-4.5-33B
  - 카드에 따르면 256K 컨텍스트를 단일 H200 또는 4×A100-40GB로 서빙할 수 있다.
  - TensorRT-LLM, vLLM, SGLang, llama.cpp를 지원한다.
  - 라이선스는 EXAONE AI Model License 1.2 - NC다. "solely for research and educational purposes. This includes evaluation, testing, academic research, experimentation…"를 허용하고 상업적 이용은 금지한다. https://huggingface.co/LGAI-EXAONE/EXAONE-4.5-33B/blob/main/LICENSE
  - EXAONE 4.0 계열(32B, 1.2B)도 같은 NC 라이선스다.
- **K-EXAONE-236B-A23B**: K-EXAONE AI Model License. "commercial and non-commercial purposes"를 허용하고, 제3자에게 상업적으로 제공하려면 별도 계약이 필요하다. https://huggingface.co/LGAI-EXAONE/K-EXAONE-236B-A23B/blob/main/LICENSE
- **FriendliAI**: Model APIs에 EXAONE이 없다(1번 참고). Dedicated Endpoints는 ExaoneMoE와 Exaone4 계열을 지원한다. https://friendli.ai/docs/changelog
- EXAONE API Platform 약관 2조 6항: 가중치가 별도 라이선스로 공개되어 있어도, 플랫폼을 통한 이용에는 플랫폼 약관이 적용된다.

**추정**

- 자체 서빙 모델은 호스팅 2.5와 가중치가 다르다. 그래서 같은 "EXAONE" 축으로 이어서 비교할 수 있는지는 별개 문제다.
- K-EXAONE 2.0의 FP8과 NVFP4 변형이 하드웨어 요구량을 얼마나 줄이는지는 확인하지 않았다.

## 확인하지 못한 것

- **실제 한도 수치:** 기본 100회/일 외에 초당과 분당 한도, TPM이나 토큰 한도, 선택 동의 후 늘어나는 일일 한도. 429 예시 헤더 값(1/s, 60/min, 86,400/day)은 예시일 뿐이다. 실패한 요청도 횟수에 들어가는지도 확인하지 못했다.
- **무료 기간과 유료 전환 계획:** 종료일과 가격은 공지되지 않았다.
- **tool calling 세부:**
  - 호스팅 API가 `tools`, `tool_choice`(`auto`, `required`, `none`, 특정 함수), `parallel_tool_calls`를 받는지와 그 동작
  - `role: "tool"` 메시지와 `tool_call_id`를 받는지
  - 스트림에서 `delta.tool_calls`가 어떤 모양으로 오는지
  - `response_format`(Structured outputs)을 받는지
- **입력 메시지의 `reasoning_content`:** 호스팅 API가 이 필드를 받아 `preserve_thinking`에 반영하는지.
- **K-EXAONE 2.5의 chat template과 tool 태그 형식:** 공개되지 않아서 2.0 template으로 추정했다.
- **`reasoning_effort`의 정확한 허용값:** `medium`이 되는지 확인하지 못했다(문서끼리 다르다). `low`에서 추론을 얼마나 줄이는지도 모른다.
- **엔드포인트 존재 여부:** `/v1/responses`와 `/v1/models`가 있는지. 문서에 없고, 호출은 금지되어 있었다.
- **모델 갱신 방식:** `metadata.weight_version`의 의미, 가중치가 바뀔 때 `model`이나 `weight_version` 값이 바뀌는지, 사전 공지를 하는지.
- **트래픽 판정:** 같은 과제를 반복 실행하는 실험이 약관 4조 1항의 "반복적인 동일 요청" 같은 비정상 트래픽으로 판정되는지.
- **비상업 범위:** 약관 2조 1항의 "비상업적 이용"에 개인이나 연구 목적의 하네스 실험과 그 결과 공개가 포함되는지. 법적 해석이 필요한 문제라 판단하지 않았다.
- **응답 의미:** 컨텍스트 524,288 토큰을 실제로 다 쓸 수 있는지(서버 측 제한), `max_tokens`를 생략했을 때의 기본값, `finish_reason`의 값 종류(`length`, `tool_calls` 등).
