# OpenAI wire API 조사: Chat Completions 기반 coding agent 하네스 관점

> 2026-11-18 서브에이전트가 1차 출처로 조사한 보고서다. 처음에는 임시 폴더에 저장했으나 재부팅으로 사라져, 2026-11-19에 대화에 남아 있던 전문으로 다시 만들었다. 다운로드한 원본 페이지와 대조 스크립트는 복구하지 못했다.

조회일: 2026-11-18. 결정이나 권고는 쓰지 않고 사실만 정리했다.

## 조사 범위와 방법

- 근거는 developers.openai.com의 API 문서, API reference, changelog, deprecations, cookbook, 블로그로 한정했다. `platform.openai.com/docs/*`로 접속하면 `developers.openai.com/api/docs/*`로 301 리다이렉트된다(2026-11-18 확인).
- 문서 페이지 대부분에는 작성일이나 수정일이 없다. 날짜가 필요한 경우 changelog 항목의 날짜를 함께 적었다. 모든 페이지는 2026-11-18에 조회했다.
- 일부 표는 텍스트가 아니라 체크 아이콘과 X 아이콘으로만 표시된다. 모델 페이지의 엔드포인트 지원 여부, apply_patch 페이지의 "API Availability" 표, Responses 이전 가이드의 기능 비교표가 그렇다. HTML의 SVG 경로를 비교해서 판별했고, 해당 항목에는 "[아이콘 판독]"을 붙였다.
- API는 호출하지 않았다. 실제 응답 동작(오류 메시지, `model` 필드 값 등)은 문서에 적힌 범위까지만 확인했다.
- 인용에 쓴 모든 페이지를 전용 폴더에 다시 받아, 인용문 113개, 아이콘 판독 결과, 가격, 날짜, 스냅샷 목록을 다시 대조했다. 모두 일치했다.
- 표기 규칙: 표시가 없는 문장은 문서에서 확인한 사실이다. "[추정]"은 문서 진술에서 끌어낸 추론이다. 인용문은 원문 그대로 영어로 옮겼다.

## 한눈에 보기

1. 현재 flagship 4종(`gpt-6.2-astra`, `gpt-6.2-sol`, `gpt-6.1-terra`, `gpt-6-luna`)은 모두 Chat Completions 엔드포인트를 지원한다.
   - 그러나 Chat Completions에서 tool을 호출할 수 있는 것은 `gpt-6-luna`뿐이고, 그것도 `reasoning_effort: "none"`일 때만이다.
   - 나머지 셋은 tool 호출에 Responses가 필요하다.
2. 문서에 따르면 GPT-5.4부터는 Chat Completions에서 tool 호출이 `reasoning_effort: "none"`일 때만 지원된다.
   - 추론과 function tool을 Chat Completions에서 함께 쓸 수 있다고 명시된 현행 모델은 찾지 못했다.
   - GPT-5.2에는 금지 문구가 없지만 허용한다는 명시도 없다.
3. `apply_patch`와 `shell` 내장 tool은 Responses 전용이다. OpenAI 공식 문서 여러 곳에서 모델이 apply_patch diff 형식(V4A)과 전용 터미널 tool로 학습되었다고 밝힌다.
4. Chat Completions 엔드포인트 자체의 지원 중단 일정은 발표되지 않았다. 문서는 "remains supported"라고 하면서 신규 프로젝트에는 Responses를 권장한다.
5. 2026-07-22부터 조직과 프로젝트 단위로 hard spend limit을 걸 수 있다. 한도에 도달하면 429로 요청을 실제로 차단한다. 다만 즉시 차단되지는 않는다.

## 1. 모델: Chat Completions + function tool 가능 여부와 스냅샷 ID

### 결론

- flagship 4종 가운데 Chat Completions에서 function tool을 쓸 수 있는 모델은 `gpt-6-luna` 하나다. `reasoning_effort`가 `"none"`일 때만 된다.
- `gpt-6.2-astra`, `gpt-6.2-sol`, `gpt-6.1-terra`는 Chat Completions 엔드포인트를 지원하지만 tool 호출은 Responses에서만 된다.
- "More models"에 남아 있는 활성 모델도 비슷하다. GPT-5.4 이후 모델은 Chat Completions tool 호출이 둘 중 하나다.
  - `none` 한정: `gpt-6-sol`, `gpt-5.6-*`, `gpt-5.5`, `gpt-5.4`, `gpt-5.4-mini`
  - 아예 불가: `gpt-6-astra`, `gpt-6.1-sol`
- GPT-5.6 이후 계열(5.6, 6, 6.1, 6.2)은 모델 페이지에 날짜가 붙은 스냅샷 ID 없이 ID 하나만 있다. 날짜가 붙은 스냅샷은 GPT-5.5 이하에만 있다.
- 응답 `model` 필드에 실제 스냅샷 ID가 찍히는지는 문서에서 확인하지 못했다.

## 2. Chat Completions의 tool 관련 기능

### 결론

- Chat Completions 요청 스키마에는 다음이 모두 있다. 따라서 API 형태로 보면 custom tool은 Responses 전용이 아니다.
  - `tools`(function, custom)
  - `tool_choice`
  - `parallel_tool_calls`
  - function의 `strict`
  - custom tool의 자유 텍스트 형식과 문법 형식(`lark`, `regex`)
- 다만 1번의 모델별 제약은 그대로 적용된다. tool 호출이 Responses 전용인 모델이 있고, `none` 한정인 모델이 있다.
- OpenAI 호스팅 내장 tool은 Chat Completions에서 web search만 된다.
- `strict`의 기본값은 API마다 다르다. Chat Completions는 기본적으로 non-strict이고, Responses는 가능하면 strict로 정규화한다.

### 세부

- **tools** (Chat Completions reference)
  - "A list of tools the model may call. You can provide either custom tools or function tools."
  - function 이름: "Must be a-z, A-Z, 0-9, or contain underscores and dashes, with a maximum length of 64."
  - "Omitting `parameters` defines a function with an empty parameter list."
- **strict** (https://developers.openai.com/api/docs/guides/function-calling)
  - Chat Completions의 `function.strict`는 "optional boolean or null (default: false)"다.
  - Function calling 가이드: "If you omit strict, the default depends on the API: Responses requests will attempt to normalize your schema into strict mode when possible, and will fall back to non-strict ... Chat Completions requests remain non-strict by default."
  - strict 모드의 요구사항: 모든 object에 `additionalProperties: false`를 두고, 모든 필드를 `required`로 지정한다. 선택 필드는 `null` 타입을 추가해서 표현한다.
  - 요구사항을 어기면 "the request will be rejected"라고 한다.
- **tool_choice** (Chat Completions)
  - 받는 값: `"none" | "auto" | "required"`, `{"type":"allowed_tools","allowed_tools":{"mode":"auto"|"required","tools":[...]}}`, `{"type":"function","function":{"name":...}}`, `{"type":"custom","custom":{"name":...}}`
  - 기본값: "`none` is the default when no tools are present. `auto` is the default if tools are present."
- **parallel_tool_calls**
  - "optional boolean (default: true)"
  - 가이드: "You can prevent this by setting parallel_tool_calls to false, which ensures exactly zero or one tool is called."
  - 가이드: "Built-in tools cannot be included in a parallel function-call batch."
- **custom tool의 Chat Completions 형태** (Chat Completions reference, Function calling 가이드)
  - 요청: `{"type":"custom","custom":{"name","description","format": {"type":"text"} | {"type":"grammar","grammar":{"definition","syntax":"lark"|"regex"}}}}`
  - 응답 `message.tool_calls`: `{"id","type":"custom","custom":{"name","input"}}`
  - Responses의 형태는 이와 다르다. 요청은 `{"type":"custom","name","description","format":{"type":"grammar","syntax","definition"}}`이고, 출력 item은 `custom_tool_call`이다.
  - GPT-5.4 가이드에는 Chat Completions custom tool 요청 예시(`model: "gpt-5.4"`, 기본 effort는 `none`)가 있다. (https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.4)
  - Function calling 가이드의 custom tool과 grammar 예시는 Responses 예시만 보여 준다.
  - "Currently, we support two forms of CFG syntax when defining grammars: lark and regex." (Function calling 가이드)
- **레거시**: `functions`와 `function_call`은 "Deprecated in favor of `tool_choice`" 및 `tools`로 표시되어 있다.
- **내장 tool** [아이콘 판독] (https://developers.openai.com/api/docs/guides/migrate-to-responses)
  - Responses 이전 가이드의 비교표에서 Chat Completions가 지원하는 것: Text generation, Audio, Vision, Structured Outputs, Function calling, Web search
  - 지원하지 않는 것: File search, Computer use, Code interpreter, MCP, Image generation, Reasoning summaries
  - 같은 가이드의 예시 설명: "With Chat Completions, you cannot use OpenAI-hosted tools natively and have to write your own tool integration."

## 3. apply_patch와 shell 내장 tool

### 결론

- `apply_patch`는 Responses API의 내장 tool 타입(`{"type":"apply_patch"}`)이다. Chat Completions와 Assistants에서는 지원되지 않는다 [아이콘 판독].
- 지원 모델은 `gpt-5.2`부터 `gpt-6.2-*`까지 문서에 나열되어 있다.
- patch 형식은 "V4A diff"라고 명시되어 있다. 다만 API 문서에 독립된 형식 명세 페이지는 없다.
  - 문서는 Agents SDK의 참조 구현 코드를 안내한다.
  - 형식에 대한 설명은 GPT-4.1 cookbook(산문)과 GPT-5.3-Codex 가이드(Lark 문법)에 있다.
- OpenAI는 여러 문서에서 모델이 이 diff 형식과 전용 터미널 tool로 학습되었다고 명시한다. 인용은 아래에 정리했다.
- `shell`도 Responses 전용이다. 문서는 "It's not available via the Chat Completions API."라고 명시한다.

### apply_patch 세부 (https://developers.openai.com/api/docs/guides/tools-apply-patch)

- 시작 문장: "Use `apply_patch` with the Responses API to propose file creations, updates, and deletions as structured diffs. Your application applies each operation and returns its result."
- 입출력 형태:
  - 출력 item은 `apply_patch_call`(`call_id`, `operation`)이다.
  - `operation.type`은 `create_file`, `update_file`, `delete_file` 중 하나이고, `path`와 `diff`를 가진다.
  - 결과는 `apply_patch_call_output`(`call_id`, `status: "completed"|"failed"`, `output`)으로 돌려준다.
- 각 operation의 의미:
  - `create_file`: "`diff` is a V4A diff representing the full file contents."
  - `update_file`: "`diff` is a V4A diff with additions, deletions, or replacements."
  - `delete_file`: "No `diff`"
- "Your patch harness is responsible for interpreting the V4A diff format and applying changes. For reference implementations, see the Python Agents SDK or TypeScript Agents SDK code."
- "When using the `apply_patch` tool, you don't provide an input schema; the model knows how to construct `operation` objects."

## 4. 추론 모델을 Chat Completions로 쓸 때

### 결론

- 지원하지 않는 파라미터는 모델과 effort에 따라 다르다.
  - GPT-6.2 계열: Chat Completions에서 `temperature`, `top_p`, `logprobs`, `top_logprobs`를 빼야 한다.
  - GPT-6과 6.1 계열: effort가 `none`이 아닐 때 같은 파라미터를 빼야 한다.
  - GPT-5.4와 5.2: 이 파라미터들을 `none`에서만 허용한다.
  - 그 밖에 신형 모델은 명시적인 `n`을 거부한다.
- Chat Completions의 파라미터 이름은 `reasoning_effort`다. 허용값은 none, minimal, low, medium, high, xhigh, max이고 모델마다 지원 범위가 다르다.
- 턴 사이의 추론 상태는 Chat Completions에서 이어지지 않는다. 공식 블로그에 "In Chat Completions, reasoning is dropped between calls"라는 문장이 있다.
- Responses에서는 reasoning item을 이어 갈 수 있다.
  - 방법은 `previous_response_id`로 잇거나, 출력 item(store:false라면 `encrypted_content` 포함)을 그대로 재전송하는 것이다.
  - 단, 모델 계열을 바꾸거나 하위 모델로 내리면 reasoning item이 제거된다.

### 지원하지 않는 파라미터

- GPT-6.2 (GPT-6.2 가이드): "Unsupported parameters: When migrating Chat Completions requests, omit `temperature`, `top_p`, `logprobs`, and `top_logprobs`. For Responses requests, omit `temperature`, `top_p`, and `top_logprobs` and remove `message.output_text.logprobs` from `include`."
- GPT-6, GPT-6.1:
  - GPT-6 가이드: "When reasoning effort is not `none`, remove `temperature`, `top_p`, and `top_logprobs`. For Chat Completions, also remove `logprobs`."
  - changelog(2026-09-03, GPT-6 Astra): "GPT-6 Astra does not support custom `temperature` or `top_p` values or log probabilities (`logprobs`)."
- GPT-5.4 (GPT-5.4 가이드, GPT-5.2 가이드에도 같은 내용): "The following parameters are only supported when using GPT-5.4 with reasoning effort set to none: temperature, top_p, logprobs. Requests that include these fields will raise an error for GPT-5.4 or GPT-5.2 with any other reasoning effort setting, or for older GPT-5 models such as gpt-5, gpt-5-mini, or gpt-5-nano."
- `n`: "Newer models reject an explicit `n`, even `n=1`." (Chat Completions reference)
- `max_tokens`: "deprecated in favor of `max_completion_tokens`, and is not compatible with o-series models." `max_completion_tokens`는 "including visible output tokens and reasoning tokens"다. (Chat Completions reference)
- reference 서두: "Parameter support can differ depending on the model used to generate the response, particularly for newer reasoning models."

### reasoning_effort

- Chat Completions reference: "`reasoning_effort: optional ReasoningEffort or null (default: "medium")` ... Currently supported values are `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, and `max`. ... Not all reasoning models support every value."
  - 실제 기본값은 모델마다 다르다. 예를 들어 GPT-5.4 계열과 5.2는 모델 페이지에 `none (default)`로 표시된다.
- Reasoning 가이드 (https://developers.openai.com/api/docs/guides/reasoning):
  - "GPT-6 Astra does not support `none` reasoning effort. Setting `reasoning.effort` (Responses) or `reasoning_effort` (Chat Completions) to `none` returns HTTP 400. GPT-6.1 Sol does not support `none` or `minimal` and defaults to `medium`."
  - "GPT-6.2 Astra and GPT-6.2 Sol reject requests that set ... to `none`."
  - "Use the Responses API for function calling. Chat Completions does not support function calling with GPT-6 Astra or GPT-6.1 Sol."
  - "Reasoning models work better with the Responses API. While the Chat Completions API is still supported, you'll get improved model intelligence and performance by using Responses."
- `reasoning.mode: "pro"`는 "GPT-5.6 and GPT-6 models support `standard` and `pro` reasoning modes in the Responses API."로 소개된다. Chat Completions에 대해서는 언급이 없다.

### 턴 사이 추론 상태

- 블로그 "Why we built the Responses API"(2025-09-22, https://developers.openai.com/blog/responses-api):
  - "Responses preserves the model's reasoning state across those turns. In Chat Completions, reasoning is dropped between calls ... That shows up in benchmarks (TAUBench +5%) and in more efficient cache utilization and latency."
  - "Chat Completions isn't going away. If it works for you, keep using it."
- GPT-5.4 가이드와 GPT-5.2 가이드: "The biggest difference, and main reason to migrate from Chat Completions to the Responses API for GPT-5.4, is support for passing chain of thought (CoT) between turns. ... Passing CoT exists only in the Responses API, and we've seen improved intelligence, fewer generated reasoning tokens, higher cache hit rates, and lower latency as a result of doing so."
- GPT-5 가이드: "we observed Tau-Bench Retail score increases from 73.9% to 78.2% just by switching to the Responses API and including `previous_response_id` to pass back previous reasoning items into subsequent requests."
- Responses 이전 가이드:
  - "Our internal evals reveal a 3% improvement in SWE-bench with same prompt and setup."
  - "Lower costs: ... (40% to 80% improvement when compared to Chat Completions in internal tests)."
- reference에서 직접 확인한 사항: Chat Completions의 assistant 메시지 입력 스키마(`role`, `audio`, `content`, `function_call`, `name`, `refusal`, `tool_calls`)에는 추론 상태를 담을 필드가 없다. 응답 `message`에도 없다.
- Responses에서 추론 상태를 다루는 방식 (Reasoning 가이드):
  - "pass back the reasoning items returned with the function calls along with the tool outputs." 방법은 `previous_response_id`를 쓰거나 모든 출력 item을 원래 순서대로 재전송하는 것이다.
  - stateless(`store: false` 또는 ZDR)에서는 "reasoning items in the response's `output` array include an `encrypted_content` property by default".
  - `reasoning.context`: `current_turn`은 이전 턴의 reasoning을 렌더링하지 않고, `all_turns`는 렌더링한다. "The GPT-5.6 model family supports `all_turns` and uses it by default. Earlier models default to `current_turn`. GPT-6.1 Sol also supports `all_turns`."
  - "For models released before GPT-5.6, the default behavior in a multi-step conversation is to carry over input and output tokens from each step without rendering reasoning from earlier turns into the next sample."
  - 제거 조건: "The API removes reasoning items if you switch model families, downgrade to a less capable model, or switch organizations or users mid-conversation as one of our safeguards against distillation. Starting with 6.2, reasoning items with a `safety_identifier` change or a modified conversation history (the prefix) will also be removed."
  - 제거 사유는 응답의 `input_transformations`에 `prefix_mismatch`, `end_user_mismatch`, `model_mismatch`, `organization_mismatch`, `turn_boundary`로 기록된다.
  - "Persisted reasoning can be reused only within the same model family."
- GPT-6.2 가이드의 "Prefix edits": "Starting with GPT-6.2, the Responses API drops reasoning items after mid-conversation edits to the conversation history (prefix edits), certain model changes (including downgrades), or changes to the end user or organization. When the model loses access to reasoning items, answer quality can decline and the model may use more tokens to repeat earlier work."
- reasoning 토큰은 API로 볼 수 없고 output 토큰으로 과금된다: "While reasoning tokens are not visible via the API, they still occupy space in the model's context window and are billed as output tokens."
- reasoning summary는 Chat Completions에서 지원되지 않는다 [아이콘 판독, 비교표].

## 5. usage 필드, 토큰 가격, 지출 상한

### 결론

- Chat Completions의 `usage` 구성:
  - 최상위: `prompt_tokens`, `completion_tokens`, `total_tokens`
  - `prompt_tokens_details`: `cached_tokens`, `cache_write_tokens`, `audio_tokens`, `image_tokens`, `text_tokens`
  - `completion_tokens_details`: `reasoning_tokens`, `accepted_prediction_tokens`, `rejected_prediction_tokens`, `audio_tokens`, `text_tokens`
- 가격(Standard, 입력 272K 이하, 1M 토큰당)은 아래 표와 같다. GPT-5.6 이후 모델은 캐시 쓰기(30분)를 입력 단가의 1.25배로 별도 과금한다.
- 조직과 프로젝트 단위의 hard spend limit이 있다.
  - 알림(spend alert)과 실제 차단(hard limit, 429)이 구분된다.
  - 차단은 즉시 이루어지지 않아 기록된 지출이 한도를 조금 넘을 수 있다.

### usage 필드 (Chat Completions reference)

| 필드 | 설명 (reference 원문) |
|---|---|
| `prompt_tokens` | "Number of tokens in the prompt." |
| `completion_tokens` | "Number of tokens in the generated completion." |
| `total_tokens` | "Total number of tokens used in the request (prompt + completion)." |
| `prompt_tokens_details.cached_tokens` | "Cached tokens present in the prompt." |
| `prompt_tokens_details.cache_write_tokens` | "The unadjusted number of prompt tokens written to cache." |
| `prompt_tokens_details.audio_tokens` / `image_tokens` / `text_tokens` | 입력 유형별 토큰 수 |
| `completion_tokens_details.reasoning_tokens` | "Tokens generated by the model for reasoning." |
| `completion_tokens_details.accepted_prediction_tokens` / `rejected_prediction_tokens` | Predicted Outputs 관련. rejected는 "still counted in the total completion tokens for purposes of billing, output, and context window limits" |
| `completion_tokens_details.audio_tokens` / `text_tokens` | 출력 유형별 토큰 수 |

- Token counting 가이드 (https://developers.openai.com/api/docs/guides/token-counting):
  - "Reported output token usage includes all tokens generated by the model, not only the text visible in a response. The Responses API reports this total as `output_tokens`, while the Chat Completions API reports it as `completion_tokens`."
  - 서식이나 구분용 토큰은 "aren't necessarily itemized separately in usage"이다. 그래서 "the reported output or completion token count can be higher than the number of visible tokens ... even when the reported `reasoning_tokens` value is `0`."
- Prompt caching 가이드 (https://developers.openai.com/api/docs/guides/prompt-caching):
  - cached-token 보고 방식이 모델마다 다르다. GPT-5.6 이후는 "Exact eligible boundary, excluding hidden tokens"이고, 이전 모델은 "Excludes hidden tokens and rounds down to a multiple of 128"이다.
  - 최소 캐시 길이는 GPT-5.6 이후 1,024 토큰이다.
- Responses의 usage에는 `input_tokens_details.cache_write_tokens_details`(`ttl_30m_tokens`, `ttl_12h_tokens`)가 있다. Chat Completions reference의 usage 스키마에는 `cache_write_tokens`만 있고 세부 항목은 없다.
- [추정] Responses 예시는 "1,000 input tokens are ordinary input: `12000 - 4000 - 7000`"로 계산한다. 즉 `input_tokens`가 cached와 write를 포함한다. Chat Completions의 `prompt_tokens`도 같은 포함 관계일 것으로 보이지만 명시 문장은 찾지 못했다.
- 같은 가이드의 비용 계산: "multiply ordinary input tokens by the model's input price, `cached_tokens` by its cached-input price, `ttl_30m_tokens` by 1.25× its input price, and `ttl_12h_tokens` by 2.5× its input price."

  - 한도는 월 단위로 초기화된다.
- "Enforcement is not instantaneous. The API Platform can process a small amount of extra usage while the limit state propagates, so recorded spend can slightly exceed the configured amount."
- 이와 별도의 한도:
  - 사용 tier에 따라 OpenAI가 승인한 월 사용 한도가 있다(`organization_usage_limit_exceeded`).
  - 선불 크레딧이 소진되면 `credit_balance_exhausted`가 반환된다.
- Terraform provider로 rate limit을 관리하고 조직과 프로젝트의 spend alert를 만들 수 있다. (https://developers.openai.com/api/docs/guides/terraform/rate-limits-and-spend)

## 6. Chat Completions 지원 중단 계획

### 결론

- Chat Completions 엔드포인트의 지원 중단이나 종료 일정은 공식적으로 발표되지 않았다. deprecations 페이지의 기능·엔드포인트 표에 없다.
- 문서는 일관되게 "remains supported"라고 쓰면서 신규 프로젝트와 장기 이전 대상으로 Responses를 권장한다.
- 실질적인 기능 격차는 있다(1번 참조).
  - GPT-5.4 이후 모델은 Chat Completions에서 추론과 tool 호출을 함께 쓸 수 없다.
  - GPT-6.x 상위 모델은 tool 호출 자체를 Responses로만 지원한다.

### 근거

- Responses 이전 가이드:
  - "While Chat Completions remains supported, Responses is recommended for all new projects."
  - "Chat Completions remains supported, so you can migrate one user flow at a time."
  - "We recommend migrating all flows to the Responses API over time to take advantage of the latest OpenAI features and improvements."
- Reasoning 가이드: "While the Chat Completions API is still supported, you'll get improved model intelligence and performance by using Responses."
- Chat Completions reference 서두: "Starting a new project? We recommend trying Responses to take advantage of the latest OpenAI platform features."
- 블로그(2025-09-22): "Chat Completions isn't going away. If it works for you, keep using it."
- deprecations 페이지의 "Feature and endpoint deprecations" 표(조회 시점)에 있는 항목은 다음과 같다. Chat Completions는 없다. (https://developers.openai.com/api/docs/deprecations)
  - `/v1/prompts`와 재사용 prompt object: 2026-11-30
  - Evals dashboard·API: 2026-11-30 read-only
  - Agent Builder: 2026-11-30
  - self-serve fine-tuning job 생성: 2027-01-06 제한
  - `/v1/audio/translations`: 2027-02-26
- 참고로 Assistants API는 종료되었다: "The Assistants API was officially sunset on August 26, 2026, and is no longer available." (Responses 이전 가이드)
- changelog의 GPT-6 Astra 항목(2026-09-03): "Tool calling requires the Responses API. If you use tools with Chat Completions, follow the Responses migration guide."

## 7. 실행 기록에 남길 만한 응답 헤더와 계정 식별 헤더

### 결론

- 문서에 나열된 응답 헤더는 `x-request-id`, `openai-processing-ms`, `openai-version`, `openai-organization`과 `x-ratelimit-*` 9종이다. 일시적인 429와 503에는 `Retry-After`가 붙을 수 있다.
- 계정을 식별하는 응답 헤더는 `openai-organization`이다. `openai-project` 응답 헤더는 문서 목록에 없다.
- 요청 헤더로는 `OpenAI-Organization`, `OpenAI-Project`, 그리고 클라이언트가 직접 정하는 `X-Client-Request-Id`가 문서화되어 있다.

### 응답 헤더 (https://developers.openai.com/api/reference/overview, "Debugging requests")

| 헤더 | 문서 설명 |
|---|---|
| `x-request-id` | "Unique identifier for this API request (used in troubleshooting)" |
| `openai-processing-ms` | "Time taken processing your API request" |
| `openai-version` | "REST API version used for this request (currently `2020-10-01`)" |
| `openai-organization` | "The organization associated with the request" |
| `x-ratelimit-limit-requests` / `-tokens` | 한도 |
| `x-ratelimit-remaining-requests` / `-tokens` | 남은 양 |
| `x-ratelimit-reset-requests` / `-tokens` | 초기화까지 남은 시간(예: `1s`, `6m0s`) |
| `x-ratelimit-limit-project-tokens` / `remaining-project-tokens` / `reset-project-tokens` | "Project-token headers may be present when a project-scoped token limit applies." |
| `Retry-After` | "The minimum number of seconds to wait before retrying a temporary rate-limit error, when present." 일시적인 429와 503(모델 과부하)에 붙을 수 있다. (https://developers.openai.com/api/docs/guides/rate-limits) |

- "OpenAI recommends logging request IDs in production deployments".
- 요청 헤더 `X-Client-Request-Id`:
  - "you can supply your own unique identifier for each request ... it must contain only ASCII characters and be no more than 512 characters long; otherwise, the request will fail with a 400 error."
  - 이 값은 "OpenAI logs this value internally for supported endpoints, including chat/completions, embeddings, responses"이다.
  - 타임아웃 등으로 `x-request-id`를 받지 못했을 때 support 조회에 쓸 수 있다.
- 요청 헤더 `OpenAI-Organization`과 `OpenAI-Project`: "If you belong to more than one organization or access projects through a legacy user API key, pass a header to specify which organization and project to use for an API request ... Usage from these API requests counts as usage for the specified organization and project."
- 요청 헤더 크기: "keep the total size of an API request's headers under 64 KiB".
- 응답 본문 쪽 참고 필드(Chat Completions reference):
  - `id`(`chatcmpl-...`), `model`, `created`, `usage`
  - `system_fingerprint`: "This fingerprint represents the backend configuration that the model runs with."
  - `service_tier`: 실제로 처리된 tier다. "This response value may be different from the value set in the parameter."

## 확인하지 못한 것

1. **응답 `model` 필드 값.**
   - 별칭으로 요청했을 때 날짜 스냅샷이 찍히는지 별칭이 그대로 찍히는지 명시한 공식 문장을 찾지 못했다.
   - GPT-5.6 이후 계열은 문서상 날짜 스냅샷 자체가 없다.
   - GPT-5.6 Sol 업그레이드 가이드는 별칭을 쓸 때 "record the returned `response.model`"이라고만 한다.
2. **GPT-5.2에서 Chat Completions의 추론 + tool 조합.** "Starting with GPT-5.4"라는 문장으로 보아 GPT-5.2는 제한 대상이 아닐 수 있다. 하지만 GPT-5.2에서 허용한다는 명시 문장은 없다.
3. **Chat Completions custom tool의 실제 동작 범위.**
   - 스키마와 GPT-5.4 예시로 존재는 확인했다.
   - 1번의 모델별 제약("tool calling requires Responses", "`none`일 때만")이 custom tool에도 똑같이 적용되는지, 위반하면 어떤 오류가 나는지는 확인하지 못했다. API를 호출하지 않았기 때문이다.
   - [추정] "tool calling"이라는 표현에는 custom tool도 포함될 것이다.
4. **GPT-6.x에 Chat Completions로 tools를 보냈을 때의 정확한 오류 코드와 메시지.** 문서에 없다. `none`을 보냈을 때 HTTP 400이 난다는 것은 GPT-6 Astra에 대해서만 명시되어 있다.
5. **`openai-project` 응답 헤더의 존재.** 문서의 응답 헤더 목록에 없다. 실제로 반환되는지는 확인하지 못했다.
6. **캐시 쓰기 과금(1.25배)이 Chat Completions에도 같은 방식으로 적용되는지.**
   - prompt caching 가이드의 "For GPT-5.6 and later, cache writes cost 1.25×"는 API를 구분하지 않고 쓰여 있다.
   - Chat Completions usage에 `cache_write_tokens`가 있으므로 적용될 것으로 보이지만 [추정], Chat Completions를 명시한 문장은 없다.
   - `prompt_tokens`에 cached와 write 토큰이 포함되는지도 Chat Completions 기준의 명시는 없다.
7. **GPT-5.5 이후 모델(5.5, 5.6, 6, 6.1, 6.2)의 apply_patch·shell 학습 여부.** 해당 가이드에서 관련 문장을 찾지 못했다. 학습 관련 명시는 GPT-4.1(cookbook), GPT-5.1, GPT-5.2, GPT-5.3-Codex, GPT-5.4 문서에만 있다.
8. **V4A의 독립된 형식 명세.**
   - API 문서에는 없다. 설명은 산문(GPT-4.1 cookbook, archived), Lark 문법(GPT-5.3-Codex 가이드), Agents SDK 코드뿐이다.
   - 내장 `apply_patch` tool의 `diff`가 cookbook의 `*** Begin Patch` envelope 형식과 정확히 어떤 관계인지는 명세로 확인하지 못했다. 예시상으로는 envelope 없이 파일 하나 단위다.
9. **문서 간 불일치.**
   - Chat Completions reference의 "Functions" 예시는 `gpt-6-astra`에 tools를 보내는 요청과 응답을 보여 준다. 이는 GPT-6 가이드와 changelog의 "tool calling requires Responses"와 충돌한다. 예시 응답의 `created`가 2023년 값이어서 예시가 모델명만 치환된 것으로 보인다 [추정].
   - Chat Completions reference는 `store`의 기본값을 `false`로 적는다. Responses 이전 가이드는 "Chat completions are stored by default for new accounts."라고 적는다.
   - Chat Completions reference의 `reasoning_effort` 기본값은 `"medium"`이다. 반면 GPT-5.4 계열과 5.2의 모델 페이지는 `none (default)`라고 적는다.
10. **문서 페이지의 작성일과 수정일.** 페이지에 표시가 없어 changelog 날짜로 대신했다.
11. **models 페이지의 "View more"나 숨겨진 목록.** "All models" 페이지(https://developers.openai.com/api/docs/models/all)로 보완했다. 그러나 계정마다 접근 가능한 모델이 다를 수 있다(rate limits 가이드: "Model access and rate limits are separate.").
