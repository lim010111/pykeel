# 09: 루프가 bash 호출을 끝까지 돌린다

**What to build:** 동기·비스트리밍 에이전트 루프다. 지시문으로 대화를 시작해 Responses 요청을 보내고, 모델이 bash를 부르면 샌드박스에서 실행해 결과를 돌려준다. 이 일을 모델이 끝낼 때까지 반복한다. 05의 Responses 어댑터와 trace, 06의 샌드박스 bash를 잇는다. 대화 상태는 하네스가 들고, 매 요청에 이전 item 전체를 보낸다(ADR-0004). 이전 item, 특히 reasoning item은 받은 그대로 돌려준다. 실행마다 모델 호출 횟수 상한과 누적 토큰 상한이 있어야 하고, 둘 중 하나라도 없거나 0이면 실행하지 않는다. 핵심 모듈에 숨은 기본값을 두지 않는다. 상한에 걸리면 실행을 멈추고 종료 이유를 trace에 남긴다. 시스템 프롬프트도 여기서 정한다. 02의 픽스처로 네트워크 없이 검증한다.

**Blocked by:** 05 트레이서, 06 샌드박스 bash

**Status:** ready-for-human

- [ ] 모델의 function_call을 샌드박스 bash로 실행하고 function_call_output으로 돌려주는 일을 모델이 끝낼 때까지 반복한다
- [ ] 이전 item(reasoning item 포함)을 받은 그대로 다음 요청에 보낸다
- [ ] tool 실행마다 trace에 종료 코드, 소요 시간, 시간 초과 여부, 잘리기 전 출력 길이가 남는다
- [ ] 모델 호출 횟수 상한이나 누적 토큰 상한이 없거나 0이면 API를 부르지 않고 거절한다
- [ ] 상한에 걸리면 실행을 멈추고, trace 마지막 줄에 종료 이유가 남는다
- [ ] plan.md 기록 원칙이 꼽은 종료 이유(정상 종료, 턴 상한, 비용 상한, 오류, 중단)가 서로 구분되어 남는다
- [ ] 02의 픽스처로 네트워크 없이 도는 동작 테스트가 있다
- [ ] 설계 메모(loop): 토큰 상한이 세는 범위(매 호출마다 다시 보내는 입력 누적을 포함하는지, 캐시 토큰을 어떻게 셀지)
- [ ] 설계 메모(llm, 내부 메시지 모델): 이전 item, 특히 reasoning item을 받은 그대로 돌려주는 방법
- [ ] 설계 메모에 예측과 실제 절을 쓰고, 참고 구현(mini-swe-agent) 비교를 덧붙인다
